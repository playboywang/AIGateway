# AIGateway

AIGateway 是一个面向多模型、多租户场景的 AI API 网关。

项目围绕稳定的 API 契约、清晰的架构边界、可靠的模型调度和完整的运行观测进行设计，为不同客户端提供统一的模型接入与治理能力。

> **当前状态：项目初始化阶段。** 仓库暂未包含可运行业务代码，后续实现将围绕明确的接口契约、数据模型和自动化测试逐项展开。

## 项目目标

- **接口稳定**：保持客户端调用方式、请求格式和响应语义清晰且可持续演进。
- **统一接入**：在一个网关中统一管理多个模型服务商、模型与 API Key。
- **稳定转发**：可靠支持流式与非流式请求，并完善超时、重试、熔断和故障切换。
- **精细治理**：支持多租户、模型路由、并发限制、用量统计和请求审计。
- **工程化设计**：以清晰边界、可测试性和可观测性作为核心架构要求。
- **平滑发布**：通过灰度、回滚和自动化验收降低服务演进风险。

## 核心能力

- `POST /anthropic/v1/messages`：Anthropic Messages 协议入口。
- `POST /chat/completions`：Chat 协议入口。
- `POST /chat/v1/messages/count_tokens`：Chat Token 数量计算入口。
- `POST /responses/v1/responses`：Responses 协议入口。
- `GET /anthropic/health`、`GET /chat/health`、`GET /responses/health`：路由健康检查。
- 客户端 API Key 鉴权与多租户隔离。
- 服务商、模型、模型 API Key 的多级配置。
- 基于优先级、并发容量和可用状态的模型选择。
- 请求日志、客户端用量统计和模型用量统计。

当前已建立独立的路由层，上游认证、模型匹配和请求转发将在服务层接入。

## 架构方向

### 模块边界

- 分离 API 层、应用层、领域层和基础设施层。
- 将服务商协议差异收敛到独立适配器，避免业务逻辑与第三方 API 细节耦合。
- 通过依赖注入和配置抽象降低组件间的隐式依赖。

### 可靠性与性能

- 使用连接池、异步 I/O 和流式背压控制提升转发效率。
- 为超时、限流、重试、熔断和故障转移建立统一策略。
- 改进模型与服务商 API Key 的并发调度，保证容量统计准确。
- 完善请求取消、客户端断连和上游异常的处理。

### 可观测性

- 统一结构化日志和请求链路标识。
- 增加延迟、吞吐、错误率、并发占用、Token 用量等指标。
- 为关键路由和调度决策提供便于排障的诊断信息。

### 安全与数据治理

- 支持密钥加密存储、脱敏展示和最小权限访问。
- 完善租户隔离、审计记录和敏感配置管理。
- 默认不提交真实密钥、数据库凭据或生产环境配置。

### 质量保障

- 以接口契约和测试用例驱动开发。
- 覆盖协议转换、流式响应、调度、失败恢复和并发边界等关键场景。
- 建立静态检查、自动化测试和持续集成流程。

## 开发原则

1. **接口稳定优先**：核心 API 的变更必须经过明确评估，避免破坏客户端集成。
2. **测试先行**：核心路由、调度和流式行为必须有自动化验证。
3. **配置与代码分离**：环境差异通过配置管理，严禁硬编码敏感信息。
4. **可观测性内建**：关键路径默认具备日志、指标和追踪信息。
5. **渐进式发布**：保证服务可灰度、可回滚、可持续验证。

## 配置管理

首次启动前复制环境变量模板：

```bash
cp .env.example .env
```

配置加载遵循明确优先级：

1. `.env` 中已存在的变量优先使用。
2. 变量未在 `.env` 中定义时，使用 `config/` 中的默认配置。

如需使用 `config/` 中的默认值，请删除或注释 `.env` 中对应的行。`.env` 已被 Git 忽略，仓库只提交 `.env.example`；禁止提交真实密钥和生产凭据。
## 本地开发

项目使用 uv 管理 Python 版本、虚拟环境、依赖和锁文件。

```bash
# 安装 Python 与项目依赖
uv sync

# 运行应用入口
uv run main.py
```

## 技术栈

服务端采用 Python 3.11+。项目使用 uv 管理解释器版本、虚拟环境、依赖和锁文件；具体 Web 框架、数据库、缓存、任务组件和部署方式将在接口契约确认后固化，并以架构决策记录（ADR）维护。
